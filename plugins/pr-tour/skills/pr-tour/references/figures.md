# 図解の形の選び方と描き方

> Phase 5-4 で各ステップの図解を作る前に読む。プラン段階（Phase 4）でも「図解:」欄に形を書くために使う。

図は「読み手が文章から組み立て直さないと見えない仕組み」を一目で見せるために置く。形は描きやすさではなく、そのステップで伝えたいことから選ぶ。1 文で言えることは図にせず、チャットの文で言う。

## 1. 伝えたいこと → 形

上から順に見て、最初に当てはまったものを選ぶ。

| そのステップで伝えたいこと | 形 | 描き方 |
|---|---|---|
| 1〜2 ホップで終わる、比べる値が 3 つ以下、差分なしで通過するだけ、名前の変更だけ | 図にしない | チャットの文で言う。表も作らない |
| 入力ごとの挙動の違い（nil／空配列／値あり）、エラーの翻訳表（例外 → ステータス・文言）、権限の組み合わせ、変更前後の比較 | 表・決定表 | `table()`。行 = 入力・条件、列 = 結果。変わったセルに `mod`、増えたセルに `new`、消えたセルに `del` |
| マイグレーションの制約一覧（NOT NULL・unique・default・index・FK） | 表 | `table()`。行 = カラム、列 = 制約。関連が変わらないなら ER 図にしない |
| テーブル同士の関連・外部キーが増えた／変わった | ER 図 | `entity()` + `link()`（両端に多重度）。関係するエンティティとカラムだけ。足したカラムは行の kind を `accent` |
| ステータス・ライフサイクルに増えた遷移／禁止された遷移 | 状態遷移図 | `state()` / `start()` / `end()` / `loop()` + `arrow()`。遷移のラベルはイベント名かメソッド名。増えた遷移は `accent`、塞いだ遷移は `warn` の破線 |
| 層・サービスをまたぐ呼び出しの順序、非同期の往復、コールバック | シーケンス図 | `lifeline()` / `msg()`。戻りは `dashed=True`。ステップ解説のトレース番号（①②…）をメッセージのラベルに揃える |
| 条件分岐・ガード節・早期 return | フローチャート | `diamond()` + `box()` + `arrow()`。全分岐を描き、この PR が足した道を `accent` |
| データがどこで変換・保存・送信されるか（イベント、キャッシュ、ジョブの引数、ETL） | データフロー | `box()` + `arrow()`。矢印のラベルに運ぶデータの名前（型・キー）を書く。保存先は `ctx` |
| どの層・どの境界（サービス、パッケージ、プロセス）に足したか | 層構造／C4 のコンテナ図 | `region()` で層・境界を囲み、中に `box()`。この PR が足した箱を `accent` |
| 型・インターフェースの実装関係、依存の向き、循環依存 | クラス図／依存関係図 | `box()` + `arrow()`（矢印は依存する側から依存される側へ）。実装は `dashed=True` |
| ファイルの追加・移動・削除、モジュールの分割 | ディレクトリのツリー | `tree()`。タグ `new` / `mod` / `del` / `ctx` / `test` |
| リトライ間隔、タイムアウト、cron の時刻、マイグレーションの実行順、デプロイ順 | タイムライン | `axis()` + `mark()`（必要なら `box()` で期間）。目盛りは実際の値（`0s` `1s` `4s`） |

判断に迷うときの目安:

- 表か ER 図か: 1 テーブルの中の話なら表、テーブルをまたぐなら ER 図
- シーケンスかフローチャートか: 「誰が誰を呼ぶか」が主題ならシーケンス、「どの条件でどこへ行くか」が主題ならフローチャート
- データフローかシーケンスか: 呼び出しの順序より「何が運ばれるか」を見せたいならデータフロー

## 2. 1 ステップ 2 枚まで

基本は 1 枚。主張が 2 つあるときだけ 2 枚にする（例: 分岐を見せるフローチャートと、入力ごとの結果を並べた決定表）。3 つ目の主張が出てきたら、ステップを割る。`plan-step.py --figure a.html b.html` のように並べて渡し、3 枚以上はスクリプトが拒否する。

1 枚の図に 2 つの主張を詰め込まない。図ごとに figcaption で主張を 1 文で書く。

## 3. 描くときの決まり

- この PR で足したものは `accent`（表では `new` / `mod`）、文脈のみは `ctx`、テストは `test`、断線や指摘の位置は `warn` か破線
- 無い経路を実線で描かない。確認できなかった経路は破線にして、ラベルか figcaption に「未確認」と書く
- 矢印にはラベルを付ける（`writes`、`enqueue`、`422 を返す`）。ラベルの無い矢印は「何か関係がある」以上の情報を持たない
- ラベルは短く。説明文は figcaption かチャットに置く
- 日本語 11px は 1 文字 ≒ 11px、ASCII は ≒ 6px。長い注記は 2 行に割って viewBox からはみ出さないようにする
- 幅 860 がカード幅の目安。図はクリックで拡大できるが、等倍で読めることを優先し、拡大を前提に詰め込まない
- 表のセルでコード片を示すときは `` `nil` `` のようにバッククォートで囲むと `<code>` になる

## 4. 拡大表示

視覚ビューの図（SVG・表・ツリー）は、クリックするか、フォーカスして Enter / Space を押すと拡大表示になる。閉じるのは Esc・背景クリック・✕。倍率はツールバーの「全体」「100%」「−」「＋」、キーボードの `+` / `-` / `0`、Ctrl（Mac は ⌘）＋ホイールで変え、大きな図はスクロールかマウスのドラッグでパンできる。仕組みは `assets/plan-view.html` の `<style id="pr-tour-figure">` と `<script id="pr-tour-lightbox">` にあり、図ごとの作業は要らない。

この仕組みが入る前のテンプレートで作った HTML には、`plan-step.py <plan.md> <plan.html> --upgrade` で同じブロックを差し込む（再開時に `plan-step.py` が warning を出したら実行する）。

## 5. 例

```python
import sys; sys.path.insert(0, "<scripts のパス>")
from fig import Fig, table, tree

# 決定表: tags の値ごとのレスポンス
t = table(
    ["tags", "変更前", "変更後"],
    [["`nil`", "500", ("422", "mod")],
     ["`[]`", "200（空）", "200（空）"],
     ["値あり", "200", ("200 + 重複を除去", "new")]],
    "Step 4: tags の値ごとのレスポンス。nil が 500 から 422 になった",
)

# 状態遷移図: cancelled が増えた
f = Fig("f5", 860, 200, "paid から cancelled への遷移が増えた")
f.start(30, 100); f.arrow([(37, 100), (90, 100)])
f.state(90, 78, 120, 44, "pending"); f.arrow([(210, 100), (300, 100)], "pay")
f.state(300, 78, 120, 44, "paid"); f.arrow([(420, 100), (520, 100)], "cancel", "accent")
f.state(520, 78, 140, 44, "cancelled", "accent")
s = f.render("Step 5: cancel() で paid から cancelled へ進む")

# ER 図: refunds が増えた
e = Fig("f6", 860, 150, "orders 1 件に refunds が複数ぶら下がる")
e.entity(40, 20, 220, "orders", [("id", "PK"), ("status", ""), ("cancelled_at", "", "accent")])
e.entity(560, 20, 220, "refunds", [("id", "PK"), ("order_id", "FK"), ("amount", "")], "accent")
e.link([(260, 50), (560, 50)], "has many", a="1", b="N")

# ツリー
r = tree([(0, "app/orders/"), (1, "cancel.rb", "new", "新設ユースケース"), (1, "refund.rb", "mod")],
         "Step 1: この PR で足したファイル")
```
