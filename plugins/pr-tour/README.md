# PR ツアーガイド（`/pr-tour`）

> [!WARNING]
> **公式マーケットプレースの `code-review` プラグインと併用するときは注意してください。**
>
> このスキルは、レビュー結果を**手元に返す** `code-review` スキル（effort レベル `low` / `medium` / `high` … と `--comment` / `--fix` を受け取るもの）を併走させる前提で書かれています。
> 公式マーケットプレース（`claude-plugins-official`）には **同じ名前の別物** の `code-review` プラグインがあり、そちらは PR を受け取ると **`gh pr comment` で GitHub にレビューコメントを投稿します**。ツアー中にそちらが起動すると、**解説のつもりで PR に公開コメントが付きます**（削除しても通知は残ります）。
>
> スキル側では、利用可能な `code-review` の説明文を見て effort 付きのものだと判別できない限り起動しない（レビュー併走を省いてツアーを続ける）ようにしてあります。それでも、公式の `code-review` プラグインを入れている環境では、ツアーを始める前に次のどちらかをおすすめします。
>
> - ツアーを行うリポジトリでは公式 `code-review` プラグインを無効化する（`/plugin` から、または `.claude/settings.json` の `enabledPlugins`）
> - 計画提示の **レビュー** 行を見て、どの `code-review` が併走しているかを確認する。意図しないものなら止める

PR の内容を **「エントリーポイントから実行が流れる順」** にツアー形式で解説するスキルです。差分をファイル単位で上から読むのではなく、リクエストやイベントが実際に通る順に歩き、各駅で **「元からあったもの」と「このPRの差分」を分けて** 示します。

## 何をするか

| Phase | やること |
|---|---|
| 0. 収集 | PR 本文・差分・触られたファイルの全体・呼び出し元／先・リポジトリの規約（`CLAUDE.md` / doc コメント / CI / lint 設定）を集める。head のリビジョンを SHA で固定して読む |
| 1. 計画提示 | 行程表（3〜7 駅）をチャットに出し、全体マップを公開して **止まる** |
| 2. ステップ実行 | 1 ステップ = 1 ターン。各駅で「すでにあったもの / このPRでの差分 / このリポジトリの約束事 / なぜこうなっているか」を示し、マップを更新して **止まる**（「次」で進む） |
| 3. 締め | できるようになったこと・まだ繋がっていない先・残る論点 |

- **文章はチャット、図解はアーティファクト**。mermaid の図（シーケンス図 / フローチャート等）を 1 枚のアーティファクトにまとめ、左サイドバーに全駅を並べてステップごとに同じ URL を更新します。過去の駅はサイドバーからいつでも戻れます
- **差分の外から差分へ到達できるか**（直接呼び出し / フレームワークの規約による結線）を file:line の根拠付きで確かめ、繋がっていない差分は「断線」として描きます。存在しない経路を捏造して線を繋ぐことはしません
- 「全部まとめて」「一気に」と言えば承認待ちを飛ばして連続実行します

## 使い方

```text
/pr-tour 123
/pr-tour https://github.com/<owner>/<repo>/pull/123
/pr-tour feat/orders-api
```

同名のスキルが他にある環境では `/pr-tour:pr-tour` と名前空間付きで呼んでください。「この PR を解説して」「PR #123 の中身を理解したい」「walk me through this PR」のように頼むだけでも起動します。別リポジトリの PR も扱えます（ローカルにクローンがあれば `git -C`、無ければ `gh api` で読み、勝手にクローンしません）。

## 前提と縮退

| 依存 | 無いときの挙動 |
|---|---|
| `git` | 必須 |
| `gh`（認証済み） | PR 番号・URL 指定に使う。無い／GitHub 以外なら、ブランチ差分と `git log` のコミットメッセージで代える |
| Artifact ツール（claude.ai のアーティファクト） | 無ければ同じ HTML をローカルファイルに書き出し、ブラウザで開いてもらう（このときだけ mermaid を CDN から読み込む） |
| effort 付きの `code-review` スキル | 無い／別物と判断したら **レビュー併走を省いてツアーを続ける**。計画の **レビュー** 行と締めに「併走なし（理由）」と明記する |
| `artifact-design` / `artifact-diagramming` スキル | あれば初回の HTML を書く前に読む。無ければ同梱の骨組み（`references/tour-map.md`）だけで書く |

ツアー自身はレビュー（良し悪しの判定）をしません。`code-review` の結果は「その場所に既知の問題があるか」として該当する駅に添えるだけで、PR へのコメント投稿や修正（`--comment` / `--fix`）は行いません。

## 構成

```
pr-tour/
├── .claude-plugin/plugin.json
├── skills/pr-tour/
│   ├── SKILL.md                 … ツアーの進め方（Phase 0〜3、歩き方、守ること）
│   └── references/tour-map.md   … 図解アーティファクトの骨組み・CSS・更新手順
├── README.md
└── LICENSE
```

## インストール

```text
/plugin marketplace add Ryu1240/ryu-skills
/plugin install pr-tour@general-skills
```
